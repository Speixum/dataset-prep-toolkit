# dataset-prep-toolkit · 数据集制备脚本

从 Labelme 多边形标注到可训练数据集的一套处理脚本：格式转换、类别分布统计、分辨率统计、掩码一致性核验、训练/测试集泄漏检查。

> **数据不随仓库发布。** 只保留处理代码，文中数字来自本地一次真实运行的输出。

## 背景

拿到的原始数据是 576 份 Labelme 多边形标注（JSON），不是模型能直接吃的分割掩码，分辨率也不统一。要变成"能训练、能评估、能交付"的数据集，中间这些活必须有人干，本仓库就是干这些活的脚本：

```
.json（多边形）  ->  像素级掩码（0/255）  ->  类别统计 / 合并  ->  核验  ->  划分  ->  交付
```

## 目录

```
dataset-prep-toolkit/
├── config.py                       # 路径与合并规则配置（唯一需要改的地方）
├── tools/
│   ├── convert_labelme_to_mask.py  # JSON -> 0/255 二值掩码
│   ├── class_stats.py              # 类别分布统计（含不平衡度）
│   ├── resolution_stats.py         # 原始分辨率分布统计
│   ├── check_masks.py              # 掩码与图像一致性核验
│   └── check_split_leakage.py      # 训练/测试跨集合泄漏检查
└── requirements.txt
```

## 环境

```bash
pip install -r requirements.txt
python --version   # 实测 3.11
```

先改 `config.py` 里的三个路径，然后任意目录下运行：

```bash
python tools/class_stats.py
python tools/resolution_stats.py
python tools/check_masks.py --split Train
python tools/check_split_leakage.py --threshold 2
python tools/convert_labelme_to_mask.py --limit 20    # 先小批量试跑
```

## 实测结果（本机真实输出）

### 1. 类别分布 —— 严重不平衡

```
标注文件数        : 576
多边形总数        : 697
类别数            : 7

类别                     多边形数      覆盖图片数       占比
------------------------------------------------
类别 1                  183         85    26.3%
类别 2                  178        167    25.5%
类别 3                  121        121    17.4%
类别 4                   93         81    13.3%
类别 5                   66         66     9.5%
类别 6                   35         35     5.0%
类别 7                   21         21     3.0%

最大/最小类样本比 : 8.7 : 1
```

**决策：7 类合并为 1 类（defect）。** 依据有两条：原始数据集说明里就写明"类别不平衡，部分缺陷类型做了合并分析"；最小两类只有 21 和 35 个多边形，单独成类既学不动又会拉低整体指标。代价是丢掉类间区分能力，这个取舍在项目记录里写明了。

### 2. 原始分辨率 —— 4 种，必须统一

```
384x288             219    38.0%
960x720             157    27.3%
880x600             147    25.5%
640x352              53     9.2%
不同分辨率种数    : 4
```

统一缩放到 **512×512**：兼顾显存与目标区域可辨性；像素归一化到 [0,1]。

### 3. 掩码与图像一致性 —— 通过

```
== Train ==                     == Test ==
图像数 528 / 掩码数 528          图像数 59 / 掩码数 59
只有图没有掩码 0                 只有图没有掩码 0
尺寸不一致     0                 尺寸不一致     0
空掩码（全黑） 0 (0.0%)          空掩码（全黑） 0 (0.0%)
```

### 4. 划分泄漏检查 —— 查到问题

```
Train 528 / Test 59
精确重复（md5）    : 0
近似重复（阈值 0）: 1     test/70.jpg  ~  train/69.jpg
近似重复（阈值 2）: 6     test/110.jpg ~  train/109.jpg (距离 1)
近似重复（阈值 4）: 10
```

同一目标物换角度、或相邻帧被分到了训练集和测试集两侧，测试分数会虚高。**这是这次整理最有价值的一条发现**：随机 9:1 划分并不严谨，正确做法是在划分之前先做相似图去重，或者按目标 ID 分组划分。

### 5. 标注覆盖率

576 份 JSON 与 587 张图一一对应上 576 张，另有 11 张图有掩码但缺源 JSON，单独记录待补。

## 五个脚本各自解决什么问题

| 脚本 | 解决什么 | 出问题时会长什么样 |
|---|---|---|
| `convert_labelme_to_mask.py` | 标注格式转换 | 模型读不了 JSON，训练代码直接报错 |
| `class_stats.py` | 类别不平衡评估 | 小类学不出来，整体指标被拉低 |
| `resolution_stats.py` | 尺寸统一决策 | 同一批数据尺寸不一，无法组 batch |
| `check_masks.py` | 图/掩码对应关系 | 掩码错位，模型学错东西还查不出原因 |
| `check_split_leakage.py` | 划分泄漏 | 测试分数虚高，上线就掉 |
